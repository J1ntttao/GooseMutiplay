# Goose Online 远端鹅与交互同步设计

## 目标

修复 0.2.0 中两台电脑进入同一关卡后远端鹅不可见、伸脖子不一致、叼取物品不同步的问题。在线模式仍然是 Steam P2P 两人模式，每台电脑只控制本机第一只鹅，第二只鹅作为远端显示对象。

## 方案

主机继续作为世界状态权威。两台电脑都把本机第一只鹅的状态发送给对方：位置、旋转、速度、伸脖子动画值、伸脖子切换状态、叼取/拖拽物品的稳定路径和拖拽标记。主机按客户端消息更新本地第二只鹅，再以可靠世界快照把主机第一只鹅和物品、NPC状态发给客户端。客户端按快照更新本地第二只鹅，并显示快照收发计数以便定位传输问题。

进入联机世界后，插件确保原版第二只鹅已激活，并把本机控制器归还给玩家 1，使玩家 2 对应的远端鹅不会被本地输入抢占。网络状态在 LateUpdate 应用，避免被原版 Goose.Update 在同一帧覆盖。携带状态发生变化时，插件按稳定路径调用原版 Holder/Dragger API，让物品仍使用游戏自己的碰撞、动画和事件逻辑。

协议版本升为 2，旧版客户端会在 Lobby/Hello 阶段被拒绝。插件版本升为 0.4.1，安装包和 README 一并更新。鹅对象按 `playerNumber` 映射，若原版世界只激活 P1，联机握手后直接初始化并激活 P2。移动快照走低延迟通道，门/开关、区域、存档和任务进度走低频可靠快照。安装器在复制 DLL 前等待游戏退出，并对短暂文件占用自动重试。

## 验证

- 协议测试覆盖新增鹅状态字段、空携带状态、携带路径和截断数据。
- Release 构建无警告无错误。
- 一键安装包校验安装、卸载、嵌入 DLL、带空格路径和 PowerShell 语法。
- 游戏日志确认 BepInEx 加载 Goose Online 0.4.1。

## 自动更新

插件启动时从仓库主分支读取 `PluginVersion`，发现远程版本更高时下载 `dist/GooseOnline.dll` 到游戏目录的 `BepInEx/update`。下载期间 UI 显示请勿关闭游戏；下载完成后启动隐藏 PowerShell 更新器，等待 `Untitled.exe` 退出后替换插件 DLL，保留 BepInEx 和其压缩包不变，最后由玩家手动重新启动游戏。网络或下载失败只记录警告，不阻塞游戏启动。
